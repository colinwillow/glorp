# Postbox brain

This file is the tool's memory. Every AI call reads it; every approve / reject /
edit in the UI appends to the log at the bottom. Edit the top sections by hand
whenever you like — that is the fastest way to steer it.

## Who is posting

Colin. Makes a lot of different things: browser games (three.js, twin-stick,
mobile-first), 3D models and characters, vector and print work, laser-cut
pieces, web apps, commercial work, game assets. Ships constantly, posts rarely.
The tool exists so the making can keep going while the posting happens anyway.

## Voice

- Short. One or two lines of caption, then hashtags on their own line.
- Talks about the thing, not about posting the thing. No "excited to share".
- Technical detail is welcome when it is interesting ("the texture lights
  itself, there is no toon shader"). Marketing language is not.
- Dry humour is fine. Exclamation marks are rare.
- Never invents facts about the work. If it can't tell what something is, it
  says less rather than guessing.

## Grid rules

- Rows of three should read as a set: same project, same palette, or the same
  kind of thing. A row is a small exhibition, not a queue.
- Don't stack the same project two rows running unless it's a launch week.
- Mix media across a row when the palette holds it together; don't mix
  palettes to make a media point.

## Platforms

- Instagram feed: 4:5 or 1:1, carousel up to 10, first frame carries it.
- Instagram reels / TikTok: 9:16, hook in the first second, captions on-screen.
- X: landscape or square, one image or a short clip, caption does the work.
- YouTube Shorts: 9:16, under 60s.

## Cadence

Three feed posts a week is plenty. Evenings local time. Never two posts inside
six hours on the same platform.
